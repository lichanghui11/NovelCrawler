# 爬虫核心逻辑笔记

## 1. 翻页逻辑的实现

### 常见误区
初学者容易陷入的死循环陷阱：
```python
# 错误示范
while current_url:
    # ... 解析逻辑 ...
    current_url = next_page_url
    # 错误原因：没有重新请求和解析，tree 对象永远是第一页的，导致无限循环处理第一页数据。
```

### 正确做法
在 `while` 循环内部，更新 URL 后，必须 **重新发起请求 (requests.get)** 并 **重新生成解析对象 (etree.HTML)**。

## 2. 智能翻页判断

在处理“下一页”按钮时，需要处理多种边界情况：

1.  **提取链接**：使用 XPath 同时查找 `<a>` (可点击) 和 `<span>` (不可点击) 标签。
    *   XPath: `//a[contains(text(), "下一页")] | //span[contains(text(), "下一页")]`
2.  **终止条件**：
    *   找不到“下一页”按钮。
    *   按钮是 `<span>` 标签（通常意味着最后一页）。
    *   `href` 属性为空。
    *   `href` 指向的链接与当前页相同。
    *   **高级判断**：`href` 指向的链接等于 **下一章的 URL**（需要结合目录元数据判断）。

## 3. 整体架构：双层循环与断点续爬

为了保证爬虫的健壮性，不建议从第一章一路“点击下一页”爬到大结局。

### 推荐架构
1.  **预先获取目录**：先爬取所有章节链接，存入 `catalog_meta.json`。
2.  **外层循环**：遍历目录列表。
    *   **优势**：支持断点续爬（检查本地文件是否存在，存在则跳过）。
3.  **内层循环**：处理单章内的分页（如 `_2.html`）。

## 4. 数据清洗（去广告）

针对小说网站常见的底部广告，采用 **位置 + 关键词** 双重过滤：

```python
ad_keywords = ["最新网址", "下载APP", "本章完"]
# 检查段落列表的最后几行
while page_lines:
    last_line = page_lines[-1]
    if any(k in last_line for k in ad_keywords):
        page_lines.pop() # 移除广告行
    else:
        break
```
