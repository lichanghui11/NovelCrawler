## 1. 项目目标与初衷

这个项目的核心目的不是为了构建一个功能最强大的爬虫，而是为了**学习和理解一个网络爬虫从零到一的构建过程**。
我的学习方法是基于我自身已有的编程基础和前端的经验，通过对比两种语言的语法和底层逻辑来对比学习和记忆，此文档是为了记录我自己的学习过程。
---

## 2. 我已经做了什么 (当前状态)

*   **回归核心流程**: 项目被精简为三个清晰的、顺序执行的阶段：
    1.  **发现 (Discovery)**: 从目录页获取所有章节信息。
    2.  **抓取 (Fetcher)**: 依次访问每个章节链接，提取内容。
    3.  **导出 (Exporter)**: 将所有抓取到的内容合并并保存为单个 `.txt` 文件。

*   **清晰的模块化结构**: 代码被组织在 `src` 目录下，并遵循了业界推荐的最佳实践：
    - `discovery.py`, `fetcher.py`, `exporter.py`: 每个文件负责一个独立的阶段，职责单一。
    - `app.py`: 作为核心工作流的“总指挥”，按顺序调用上述模块。
    - `main.py`: 位于项目根目录，是一个非常“薄”的启动器，只负责调用 `app.py` 中的主流程。

当前可以算是一个**破碎版本的 mvp**，因为功能简陋，也不能跑起来，我需要在阅读的代码之后进行学习和改动，彻底理解里面的逻辑，才能让这个 mvp 真正跑起来。

## 3. 下一步学习计划 (Learning Roadmap)

在完全理解当前这个极简版本的基础上，我计划逐步将高级功能以“学习模块”的形式添加回来。这能让我清晰地看到每个功能解决了什么问题，以及它是如何实现的。

下一步的学习路线图可能包括：

1.  **实现简单的断点续爬**: 引入一个简单的状态文件（如 JSON），记录已完成的章节，避免重复抓取。
2.  **优化内存使用**: 将抓取逻辑修改为“抓取一章，保存一章”，而不是将所有内容都放在内存里。
3.  **提升抓取效率**: 引入 `concurrent.futures` 线程池，实现并发抓取，直观感受性能提升。
4.  **升级输出格式**: 学习使用 `ebooklib` 库，将导出模块从生成 `.txt` 升级为生成更美观的 `.epub` 电子书。
5.  **引入数据库**: 使用 `SQLite` 替代简单的状态文件，实现更健壮、更可靠的状态管理。
6.  **构建命令行接口 (CLI)**: 使用 `argparse` 模块，让我们可以通过命令行参数（如 `python main.py fetch`）来控制爬虫的不同行为。
